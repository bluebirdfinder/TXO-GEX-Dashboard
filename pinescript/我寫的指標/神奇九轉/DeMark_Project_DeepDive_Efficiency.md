# 🧠 Antigravity Deep Dive：節流協議與開發效率

這份文件解釋了為什麼我們在開發 TradingView 指標時，需要切換模型與外部化記憶。

## 1. 為什麼對話越長，AI 會變笨？
當對話來到第 30、40 個回合時，AI 必須在極短時間內處理龐大的歷史資訊。
這會導致「資訊稀釋」，AI 可能會開始：
*   忘記您在第 5 回合提到的特定顏色代碼。
*   遺漏指標中的某個過濾條件。
*   消耗極大量的 Token，導致您的額度迅速耗盡。

## 2. 外部記憶 (Project State) 的運作邏輯
我們建立 `Project_State.md`，就像是為專案建立一個「存檔點」。
*   **重置代價**：開啟新對話只需讀取這個幾百字的檔案，而不用讀取幾萬字的歷史紀錄。
*   **精準度**：因為上下文非常乾淨，AI（特別是 Claude）的邏輯推理能力會回到巔峰狀態。

## 3. 模型分工的經濟學
*   **Gemini Pro (High)**：像是一位「博學的圖書館管理員」。他看書極快（Context 大），適合掃描文件與整體架構。
*   **Claude Sonnet**：像是一位「拿著顯微鏡的精密工程師」。他對邏輯的嚴謹度極高，適合處理 Pine Script 中最難搞的迴圈與條件判斷。
*   **交替使用**：能讓我們在預算（額度）與品質之間取得完美平衡。
