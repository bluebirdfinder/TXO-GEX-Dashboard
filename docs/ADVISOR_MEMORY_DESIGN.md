# 幕僚鳥記憶設計（2026-10-16）——給洋洋專案參考的交接

來源：TXO-GEX-Dashboard 的 `trading room/advisor_bridge.py`。起點是洋洋的分層記憶（重要度、封存、每週睡眠整理、程式比對變動清單），
這次往「人腦怎麼記、怎麼忘、怎麼想起」多走了幾步。**沒有跑過對照實驗，只在模擬資料與少量實測上驗證過**，採用前請自己小規模試。

## 一、洋洋已經做得好、我直接沿用的

- 重要度 1/2/3，核心不自動淡化；遺忘＝封存可還原；每週整理前先備份；
- 變動清單由程式比對產生、不經模型；回顧失敗就不動記憶、不更新狀態。

## 二、我多加的（可搬過去的）

| # | 做法 | 人腦對照 | 解決洋洋的什麼問題 |
|---|---|---|---|
| 1 | **ACT-R 啟動值淡化**：`B = ln Σ (距今天數+1)^-0.5`，每條記憶記「被想起的日期清單」。取代「90 天沒用就降級」 | 冪次遺忘曲線＋提取強化：越常想起越牢，久沒想起自然下沉 | 固定 90 天一刀切：常用但沒走 `recall` 的記憶會被誤降；用過 10 次和用過 1 次的待遇相同 |
| 2 | **三因子提取**：相關度×重要度×近期活躍度排序，核心一律帶入，其餘取前 12 條，不相關的只留 3 條底噪（Park et al. 2023 Generative Agents） | 想起的是「此刻有用的」，不是全部 | 記憶越長越大時，全部塞進去會稀釋、也燒額度 |
| 3 | **商品／主題標籤＋擴散激發**：問題（含目前正在看的商品＝情境線索）的標籤命中記憶權重 1.0，與命中記憶共用標籤的鄰居 0.4（一跳） | 聯想記憶、情境依賴記憶 | 洋洋背景訊息「不讀舊對話、記憶不一定帶進去」（D-30 之後的 10/7 事件）：標籤可以讓背景任務用「情境」撈對的記憶 |
| 4 | **取代而非覆寫**：修正時舊條目封存、新條目 `supersedes` 指向舊的 | 重新鞏固會改寫記憶，但保留「以前是怎樣」才能追溯 | 9/30 的「說自己婉拒過」：記憶被改寫後無從對質 |
| 5 | **前瞻記憶（提醒）**：記憶可帶 `remind_on`；到期且未完成的待辦、即將到期（2 天內）的事實，會在回答最前面主動提醒 | 「記得要做某事」是另一套記憶 | 洋洋目前提醒是獨立的 reminders.json；可考慮和記憶共用同一套 |
| 6 | **行為模式反思＋確認流程**：每週回顧時模型只能提「候選模式」，每條要有 ≥2 條**逐字出現在對話裡的證據**（程式驗證，編的直接丟掉）；使用者說「確認模式」才寫成核心記憶，「否決模式」後永不再提；重複出現只累積證據 | 反思（Generative Agents）＋「推論不等於事實」 | 避免模型把推論當成使用者說過的事寫進記憶（D-30 的記憶錯亂就是這類） |
| 7 | **親身教訓自動核心化**：虧損、被軋這類情緒強烈的事件重要度一律 3 | 杏仁核標記：情緒強的事記得牢 | 洋洋的「重要的關係事實另外存成重要度 3」是同一個想法，這裡寫進提示詞規則 |
| 8 | **每次呼叫獨立、不維持長 session**：每次 `claude -p` 無狀態，靠「長期記憶＋近 8 輪／36 小時短期記憶」重建上下文 | 工作記憶很小，其餘靠長期記憶 | 洋洋 session 長到 21 萬 token、被模型自己摘要兩次丟細節（D-30、9/30）。**代價**：沒有真正的連續對話感，對聊天型助理可能不合適 |

## 三、洋洋有、我沒有的（不要以為我比較完整）

- 自己的 MCP 工具伺服器（日曆、信箱、提醒、查詢…）；我的幕僚鳥關掉全部工具，只回答。
- Telegram 橋接、白名單、額度佇列、分段送出、主動關心與情感設定。
- session 濃縮換 session 的完整機制（`session_rotate.py`）與回滾。
- 使用政策界線與隱私分級的整套規範。

## 四、最值得先試的三件（成本低、風險低）

1. 把「90 天降級」換成啟動值（#1）：只動 `weekly_consolidation.decay()`，`memories.json` 每條加一個 `uses` 日期清單，`recall` 時附加今天。
2. 取代而非覆寫（#4）：`update_memory` 改成封存舊的＋新增帶 `supersedes` 的新條目。
3. 行為模式候選要有逐字證據（#6）：如果洋洋以後想讓她「觀察」使用者，這道驗證能擋掉編造。
